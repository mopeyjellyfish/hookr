# Build A Host And Plugin With FlatBuffers

This tutorial is listed under the Diataxis Tutorials section:
[Tutorials Index](./tutorials/index.md).

This tutorial walks through a complete Hookr contract using the
`urlbalancer` example in
[`testdata/contracts/urlbalancer`](https://github.com/mopeyjellyfish/hookr/tree/main/testdata/contracts/urlbalancer).

You will:

1. define a FlatBuffers contract,
2. generate Hookr glue,
3. implement a TinyGo plugin,
4. build the plugin to Wasm,
5. implement a Go host,
6. call the plugin through the generated SDK.

This is a tutorial for Go developers integrating Hookr into their own
application. The same pattern applies to any other contract: the application
defines the schema, and Hookr handles the Wasm ABI, validation, and generated
host/plugin glue.

## Prerequisites

Install the Hookr CLI:

```bash
go install github.com/mopeyjellyfish/hookr/cmd/hookr@latest
```

Install the required build tools:

```bash
brew install flatbuffers tinygo
```

This tutorial assumes you are working from the Hookr repository root.

## Step 1: Write The FlatBuffers Contract

Create a schema file. In this repository the example lives at
[`testdata/contracts/urlbalancer/urlbalancer.fbs`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/urlbalancer.fbs).

```fbs
namespace Hookr.Test.UrlBalancer;

file_identifier "URLB";

table Empty {}

table PluginInfo {
  name:string;
  version:string;
  description:string;
}

table BalanceRequest {
  url:string;
  nodes:[string];
}

table BalanceResponse {
  valid:bool;
  normalized_url:string;
  scheme:string;
  host:string;
  selected_node:string;
  selected_index:uint32;
  rng_int:int32;
  rng_float:float32;
  error:string;
}

table RngIntRequest {
  min:int32;
  max:int32;
}

table RngIntResponse {
  value:int32;
}

table RngFloatRequest {}

table RngFloatResponse {
  value:float32;
}

rpc_service Plugin {
  GetInfo(Empty):PluginInfo;
  Balance(BalanceRequest):BalanceResponse;
}

rpc_service Host {
  RngInt(RngIntRequest):RngIntResponse;
  RngFloat(RngFloatRequest):RngFloatResponse;
}
```

### Part By Part

`namespace Hookr.Test.UrlBalancer;`

- Puts the generated FlatBuffers types into a stable namespace.
- Hookr uses the schema structure and service metadata, but FlatBuffers still
  owns the underlying type generation.

`file_identifier "URLB";`

- Gives the binary FlatBuffers payload a short identifier.
- This is optional for Hookr itself, but useful and standard in FlatBuffers
  contracts.

`table Empty {}`

- A reusable empty request type.
- `GetInfo` does not need input, so it uses `Empty`.

`table PluginInfo { ... }`

- The plugin returns metadata the host can inspect.
- This table is specific to this application. Hookr does not impose it.

`table BalanceRequest { ... }`

- `url` is the user input the plugin validates.
- `nodes` is the list of backend nodes the plugin may choose from.

`table BalanceResponse { ... }`

- `valid`, `normalized_url`, `scheme`, and `host` describe the parsed URL.
- `selected_node` and `selected_index` tell the host where the plugin routed.
- `rng_int` and `rng_float` show values returned from host callbacks.
- `error` lets the plugin report a validation or routing failure.

`table RngIntRequest/Response` and `table RngFloatRequest/Response`

- These types describe host callbacks, not host-to-plugin requests.
- The plugin uses them when it asks the host for random values.

`rpc_service Plugin { ... }`

- `Plugin` is the service the host calls.
- `GetInfo` and `Balance` are application-defined plugin methods.

`rpc_service Host { ... }`

- `Host` is the callback service the plugin can call back into.
- The host exposes `RngInt` and `RngFloat` to the plugin.

This is the core Hookr rule: your application defines the contract in
FlatBuffers, and Hookr turns that contract into a typed plugin system.

## Step 2: Generate Hookr Glue

Run:

```bash
hookr gen \
  --schema ./testdata/contracts/urlbalancer/urlbalancer.fbs \
  --out ./testdata/contracts/urlbalancer/gen \
  --package urlbalancerhookr
```

This does two jobs:

1. it runs `flatc` so you get normal FlatBuffers Go types,
2. it generates Hookr-specific SDK/PDK files around those types.

The generated package ends up in
[`testdata/contracts/urlbalancer/gen/urlbalancerhookr`](https://github.com/mopeyjellyfish/hookr/tree/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr).

Important generated files:

- [`BalanceRequest.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr/BalanceRequest.go)
  and the other FlatBuffers type files:
  generated by `flatc`, they define the contract types.
- [`contract_meta_gen.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr/contract_meta_gen.go):
  generated by Hookr, it contains method IDs and schema metadata.
- [`host_sdk_gen.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr/host_sdk_gen.go):
  generated by Hookr, it gives the host `Open`, `Close`, and typed method
  calls like `Balance`.
- [`plugin_pdk_gen.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr/plugin_pdk_gen.go):
  generated by Hookr, it gives the plugin `MustRegisterPlugin`, the
  `Plugin` interface, and callback helpers like `ctx.RngInt(...)`.

## Step 3: Understand The Generated Host API

The host side of the generated package is the API application code uses to load
and call a plugin.

In
[`host_sdk_gen.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/gen/urlbalancerhookr/host_sdk_gen.go)
the important parts are:

```go
type Config struct {
	WasmPath       string
	FileOptions    []hookrruntime.FileOption
	Host           Host
	RuntimeOptions []hookrruntime.Option
}

type Host interface {
	RngInt(ctx context.Context, req *RngIntRequestT) (*RngIntResponseT, error)
	RngFloat(ctx context.Context, req *RngFloatRequestT) (*RngFloatResponseT, error)
}

func Open(ctx context.Context, cfg Config) (*Runtime, error)

func (r *Runtime) GetInfo(ctx context.Context, req *EmptyT) (*PluginInfoT, error)
func (r *Runtime) Balance(ctx context.Context, req *BalanceRequestT) (*BalanceResponseT, error)
```

### Part By Part

`Config`

- `WasmPath` tells Hookr which plugin Wasm module to load.
- `FileOptions` controls trust policy for the Wasm artifact.
- `Host` is your implementation of the host callback service.
- `RuntimeOptions` exposes lower-level runtime tuning when needed.

`Host interface`

- Hookr generates one method per `rpc_service Host` method.
- If your schema adds more host callbacks, this interface grows with it.

`Open`

- loads the Wasm module,
- validates the contract handshake,
- binds the host callback methods,
- returns a typed runtime wrapper.

`Runtime.GetInfo` and `Runtime.Balance`

- are generated from `rpc_service Plugin`,
- hide method IDs and wire encoding,
- let the host call plugin methods as normal Go methods.

## Step 4: Write The Plugin

The example plugin lives at
[`testdata/contracts/urlbalancer/plugin/main.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/plugin/main.go).

```go
//go:build wasip1

package main

import (
	"net/url"

	urlbalancerhookr "github.com/mopeyjellyfish/hookr/testdata/contracts/urlbalancer/gen/urlbalancerhookr"
)

type plugin struct{}

func (plugin) GetInfo(_ *urlbalancerhookr.PluginContext, _ *urlbalancerhookr.EmptyT) (*urlbalancerhookr.PluginInfoT, error) {
	return &urlbalancerhookr.PluginInfoT{
		Name:        "urlbalancer",
		Version:     "1.0.0",
		Description: "Selects a backend node for a URL using host-provided RNG callbacks.",
	}, nil
}

func (plugin) Balance(ctx *urlbalancerhookr.PluginContext, req *urlbalancerhookr.BalanceRequestT) (*urlbalancerhookr.BalanceResponseT, error) {
	resp := &urlbalancerhookr.BalanceResponseT{}
	if req == nil {
		resp.Error = "request is required"
		return resp, nil
	}

	parsed, err := url.Parse(req.Url)
	if err != nil {
		resp.Error = err.Error()
		return resp, nil
	}
	if parsed.Scheme == "" || parsed.Host == "" {
		resp.Error = "url must include scheme and host"
		return resp, nil
	}
	if len(req.Nodes) == 0 {
		resp.Error = "at least one node is required"
		return resp, nil
	}

	rngIntResp, err := ctx.RngInt(&urlbalancerhookr.RngIntRequestT{
		Min: 0,
		Max: int32(len(req.Nodes) - 1),
	})
	if err != nil {
		return nil, err
	}

	rngFloatResp, err := ctx.RngFloat(&urlbalancerhookr.RngFloatRequestT{})
	if err != nil {
		return nil, err
	}

	index := int(rngIntResp.Value)
	if index < 0 || index >= len(req.Nodes) {
		resp.Error = "host returned rng index outside node range"
		return resp, nil
	}

	resp.Valid = true
	resp.NormalizedUrl = parsed.String()
	resp.Scheme = parsed.Scheme
	resp.Host = parsed.Host
	resp.SelectedNode = req.Nodes[index]
	resp.SelectedIndex = uint32(index)
	resp.RngInt = rngIntResp.Value
	resp.RngFloat = rngFloatResp.Value
	return resp, nil
}

//go:wasmexport hookr_init
func hookrInit() {
	urlbalancerhookr.MustRegisterPlugin(plugin{})
}

func main() {}
```

### Part By Part

`//go:build wasip1`

- Marks this file as the Wasm/TinyGo build target.
- The host example uses a separate non-Wasm build tag.

`import urlbalancerhookr ...`

- The plugin imports the generated package.
- There is no hand-written transport code.

`type plugin struct{}`

- Your plugin can be any Go type.
- It just needs to implement the generated `Plugin` interface.

`GetInfo(...)`

- Implements the generated plugin method for `Plugin.GetInfo`.
- It receives the generated `PluginContext` and generated request type.
- It returns the generated response type.

`Balance(...)`

- Implements the application logic.
- Reads `req.Url` and `req.Nodes`.
- Uses normal Go code to parse and validate the URL.
- Calls `ctx.RngInt(...)` and `ctx.RngFloat(...)` to invoke generated host
  callbacks.
- Builds and returns a `BalanceResponseT`.

`hookr_init`

- This is the one required registration step.
- `MustRegisterPlugin(plugin{})` tells Hookr which implementation handles the
  generated `Plugin` service.

`main() {}`

- TinyGo still needs a `main` package entrypoint, even though Hookr drives the
  Wasm exports.

## Step 5: Build The Plugin

Run:

```bash
hookr build \
  --plugin ./testdata/contracts/urlbalancer/plugin \
  --out ./testdata/contracts/urlbalancer/bin/urlbalancer.wasm
```

This is the TinyGo-first Hookr build path. Hookr handles the TinyGo build
command so users do not need to remember flags.

The output Wasm module is written to:

- `./testdata/contracts/urlbalancer/bin/urlbalancer.wasm`

## Step 6: Write The Host

The example host lives at
[`testdata/contracts/urlbalancer/examples/host_main.go`](https://github.com/mopeyjellyfish/hookr/blob/main/testdata/contracts/urlbalancer/examples/host_main.go).

```go
//go:build !wasip1

package main

import (
	"context"
	"fmt"
	"log"
	"path/filepath"

	urlbalancerhookr "github.com/mopeyjellyfish/hookr/testdata/contracts/urlbalancer/gen/urlbalancerhookr"
)

type host struct{}

func (host) RngInt(_ context.Context, req *urlbalancerhookr.RngIntRequestT) (*urlbalancerhookr.RngIntResponseT, error) {
	midpoint := req.Min
	if req.Max > req.Min {
		midpoint = req.Min + ((req.Max - req.Min) / 2)
	}
	return &urlbalancerhookr.RngIntResponseT{Value: midpoint}, nil
}

func (host) RngFloat(_ context.Context, _ *urlbalancerhookr.RngFloatRequestT) (*urlbalancerhookr.RngFloatResponseT, error) {
	return &urlbalancerhookr.RngFloatResponseT{Value: 0.5}, nil
}

func main() {
	ctx := context.Background()
	wasmPath := filepath.Join("testdata", "contracts", "urlbalancer", "bin", "urlbalancer.wasm")

rt, err := urlbalancerhookr.Open(ctx, urlbalancerhookr.Config{
	WasmPath: wasmPath,
	FileOptions: []hookrruntime.FileOption{
		hookrruntime.WithAllowUnsigned(),
	},
	Host: host{},
})
	if err != nil {
		log.Fatal(err)
	}
	defer func() {
		if err := rt.Close(ctx); err != nil {
			log.Fatal(err)
		}
	}()

	info, err := rt.GetInfo(ctx, &urlbalancerhookr.EmptyT{})
	if err != nil {
		log.Fatal(err)
	}

	result, err := rt.Balance(ctx, &urlbalancerhookr.BalanceRequestT{
		Url:   "https://example.com/api",
		Nodes: []string{"node-a", "node-b", "node-c"},
	})
	if err != nil {
		log.Fatal(err)
	}

	fmt.Printf("%s %s -> %s\n", info.Name, info.Version, result.SelectedNode)
}
```

### Part By Part

`type host struct{}`

- The host implementation can be any Go type.
- It just needs to satisfy the generated `Host` interface.

`RngInt(...)`

- Implements the `Host.RngInt` callback from the schema.
- Receives a generated request type and returns a generated response type.
- In this example it picks the midpoint, which keeps the example deterministic.

`RngFloat(...)`

- Implements `Host.RngFloat`.
- Returns a fixed `0.5` so tests and docs stay predictable.

`urlbalancerhookr.Open(...)`

- loads the Wasm plugin,
- validates the schema handshake,
- applies the configured file trust policy,
- registers `host{}` as the callback provider,
- returns a typed runtime wrapper.

`rt.GetInfo(...)`

- calls the plugin's `GetInfo` method through the generated SDK.

`rt.Balance(...)`

- sends a typed `BalanceRequestT` to the plugin,
- receives a typed `BalanceResponseT`,
- hides all Wasm transport details from the host code.

## Step 7: Run The Host Against The Plugin

After generating and building the plugin, run the host example:

```bash
go run ./testdata/contracts/urlbalancer/examples/host_main.go
```

The host will:

1. open the built Wasm plugin,
2. call `GetInfo`,
3. call `Balance`,
4. print the selected node.

With the example host implementation, the midpoint callback selects `node-b`:

```text
urlbalancer 1.0.0 -> node-b
```

## Recap

For a Hookr integration, the host application author writes:

1. one FlatBuffers schema,
2. one host implementation for `rpc_service Host`,
3. one plugin implementation for `rpc_service Plugin`.

Hookr generates and manages:

- FlatBuffers-backed Go types,
- method IDs,
- contract metadata,
- startup validation,
- Wasm transport,
- typed host SDK calls,
- typed plugin callback helpers.

That is the intended Hookr experience: the application owns the contract, and
Hookr turns it into a small, typed host/plugin API.
